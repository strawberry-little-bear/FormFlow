# 评审档案：来源资料如何进入需求 Agent

## 场景

在本地演示环境中，组织者上传虚构的通知、名单和报名模板，再发送一条需求整理请求。演示使用空的 `FORMFLOW_LLM_API_KEY`，覆盖 1440、390 和 320 像素视口。

## 观察

- 三份资料由服务器保存，页面只展示资料编号、文件元数据和解析状态。
- Agent 请求携带任务范围内的真实 `src_*` 资料编号；服务端按编号加载原始文件，浏览器不能用正文替换资料编号。
- 支持文件输入的模型可优先读取原始材料；不支持或调用失败时才进入文字解析/OCR 降级，页码和未读范围会保留在上下文中。
- 没有模型密钥时，原始要求仍保留在草案中，页面提示可使用模板或手动编辑，不提供不会成功的重复重试。
- 三种视口均无整页横向溢出，没有控制台错误或失败请求。

## 复现入口

```powershell
$env:FORMFLOW_LLM_API_KEY = ''
$env:FORMFLOW_WALKTHROUGH_BASE = 'http://127.0.0.1:8012'
node scripts/ux_requirements_materials_walkthrough.cjs
```

脚本会输出资料编号、Agent 请求、无密钥降级状态和移动端截图；临时数据写入 `data/`，不会进入版本库。

## 结论与边界

本档案验证资料边界、请求合同和无密钥体验，不代表真实 provider 的文件输入兼容性、语义准确率、视觉排版判断或数据留存政策。蓝图必须由组织者确认后才能发布。
