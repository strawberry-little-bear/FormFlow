# FormFlow 黑客松演示指南

目标：5 分钟解释“不是又一张表单”，并展示真实可操作的核心闭环。全部人物、材料、资格与结论均为虚构；不要把种子桩当作真实模型效果。

## 演示前（提前完成，不占台上时间）

1. 按 README 使用独立 `data/demo/` 数据库和存储；安装依赖、执行种子。**重新种子会重置演示任务与凭证及附件**，不能连接业务库。
2. 启动 API；若要演示新提交检查，同时启动相同环境下的单 Worker。预生成证据不要求真实模型，现场不要临时配置或泄露密钥。
3. 用 `demo / demo1234` 登录组织者；另一个浏览器/独立会话预先用赵六凭证打开提交者空间，不在投屏画面展示完整凭证。
4. 工作台核对：名册5、免交1、应交4、正式3、未正式1、验收1。任务截止由种子按执行时刻生成，以页面任务时区为准。
5. 真实演示前先完整走一遍；准备本仓库截图作为网络/环境失败时的静态备份，但明确说是截图而非在线结果。

## 0:00–0:40｜问题与价值

> 收材料最难的不是发出表单，而是交上来以后：谁没交、谁要改、哪版验收、最终包里是哪一版。我们把这些环节做成一条有证据、有版本的工作流。

打开收集工作台。说明应交分母排除有效免交；正式提交、材料检查、资格和人工验收不是一个“通过”按钮。

## 0:40–1:40｜把问题指给人看

打开李四的「复核」，选择期次规则：展示要求来源、报告第2期的原文引用、任务第1期的要求和补正建议。

- 不是只有红色状态，而是“哪里不符、依据什么、下一步怎么改”。
- `unknown` 是无法判断，`failed` 是技术未完成，都不是确认材料缺失。
- 选择“确认问题”仍然保留补正，不要为了演示把问题错误地解除。

## 1:40–2:50｜人能放心接手

回工作台打开王五：

1. 在姓名规则写一段虚构复核理由，暂不提交；同时可写独立资格依据和验收依据。
2. 刷新页面：看到三类理由恢复，明确“暂存不等于提交决定”。
3. 点击「下一待处理」：到人工终验项，原规则理由不串入；再切回能恢复。
4. 三步导航分别到材料、资格、验收；显示验收前置待办。所有快捷跳转仅导航，不替人决定。
5. 如要实际提交：在核对演示材料后选“人工核对通过”，写理由、提交；对剩余阻塞项逐一核对。全部前置满足后，**单独写验收依据**再验收。

解释：补交新正式版本、成员变化或检查证据变化后，旧理由不自动套用；旧页面请求会被后端拒绝并要求刷新。成员/补交冲突可用本轮验收证据讲解，不必现场修改数据库。

## 2:50–3:40｜提交者不是在和表单搏斗

切到预先打开的赵六提交空间，默认完整表单：

- 故意缺一项时，正式提交的错误摘要能定位到字段/附件；不完整内容可以保存草稿。
- 需要时切逐步引导；未点“下一题”的输入也暂存。
- 上传成功不是正式提交，正式提交才产生回执和不可变版本。

没有模型配置时，不现场承诺新语义检查成功；无 Worker 时明确新任务会排队。不要为了追求顺畅隐藏故障态。

## 3:40–4:30｜交付不拿错版本

组织者进入「交付与归档」：

- 创建正式快照（会写入本地演示库），核对纳入/排除明细。
- 未改变种子时正式包只纳入张三；若现场验收了王五，应按当前实际状态说明，不再套用初始人数。
- 下载 CSV 与 ZIP，说明它们引用同一快照。新补交不会静默替换已经生成的包。
- 催交只是可复制通知内容，未对外发送。

## 4:30–5:00｜双 Agent 与下一步

打开「需求设计」介绍已发布蓝图/历史预览，不在冻结版本上直接发布。展示未发送输入、复用历史后的草案及发布前差异核对（演示库可变更，但不必真的发布）。

> 需求 Agent 整理要求，审核 Agent 找证据；程序守住权限、版本、预算与快照；最终资格与验收由人负责。下一步先做目标用户试走和错误评估，而不是承诺模型准确率。

## 常见情况与坦诚兜底

| 现象 | 检查/讲解 |
| --- | --- |
| 新提交一直排队 | 检查 Worker 是否启动且环境与 API 一致 |
| 新语义规则失败 | 检查模型配置/预算；收件和回执仍保留，显示未完成并交人工 |
| 理由没有恢复 | 确认同一标签页、账号、主体、版本、成员和运行；范围变化不恢复是防误用保护；存储失败会提示 |
| 演示数目不对 | 是否已补交/验收/免交；不要重置正在使用的业务库 |
| 无法验收 | 看服务端阻塞列表，不能用验收按钮绕开规则/资格前置 |
| 投屏暴露凭证 | 停止展示并撤销重发；真实凭证不进截图、README 或提交记录 |

完成演示后，只清理由草稿不会撤销已提交决定；需要重置时停止演示、确认独立库路径后再执行种子。
