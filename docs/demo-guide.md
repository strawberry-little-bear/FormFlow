# FormFlow 体验指南

这份指南面向第一次打开 FormFlow 的访客。它用一组虚构数据展示完整流程：组织者整理要求、提交者提交材料、审核 Agent 逐项取证，组织者确认后导出交付快照。演示数据和离线审核轨迹只用于说明产品行为，不代表真实模型准确率。

## 启动演示

```bash
python scripts/start_demo.py --reset
```

启动后打开终端显示的地址，使用组织者账号 `demo / demo1234` 登录。提交者账号和一次性凭证由种子脚本生成；不要把真实凭证放进截图、日志或提交记录。

演示环境使用独立的 `data/demo/` 数据库和附件目录。需要保留当前进度时直接重新启动；只有要恢复初始数据时才使用 `--reset`。如果默认端口被占用，可指定其他端口：

```bash
python scripts/start_demo.py --port 8010
```

只检查本地依赖、API、Worker、Agent runtime 和只读 MCP sidecar 时使用：

```bash
python scripts/start_demo.py --check --port 8010
```

## 体验组织者路径

### 1. 从资料整理收集任务

在“需求设计”中上传或粘贴通知、名单、模板和补充说明。需求 Agent 会生成一份可编辑的收集蓝图，包含：

- 适用提交者和身份字段；
- 材料槽位、格式、数量、命名和页数要求；
- 截止时间、补正时间和跨材料核验规则；
- 来源引用、资料冲突和需要确认的问题。

草案在组织者确认并发布前不会成为正式规则。模型没有配置时，演示仍会展示预置的离线轨迹，并明确标记为离线结果。

上传的原始文件会保留在当前任务的私有资料区，页面显示文件名、大小和解析状态。它们只通过资料编号进入 Agent 请求；需要删除已被草案引用的资料时，系统会保留追溯链并提示不能删除。

### 2. 查看收集进度

进入“收集工作台”查看应交、免交、已提交和已验收的分组。打开某位提交者可以看到下一步动作；催交通知会排除免交、已提交和已过截止且不再适用的人。

### 3. 按规则检查材料

在“证据复核”中打开李四的提交。每条规则都显示结论、解释、来源文件和页码或位置：

- `satisfied`：已有证据支持规则；
- `issue`：发现需要处理的问题；
- `unknown`：证据不足，需要人工判断；
- `failed`：检查过程没有完成。

证据引用是模型给出的定位线索，程序会校验文件 ID、位置格式和引用非空，但组织者仍应打开原文核对。确认问题不会跳过补正或验收前置条件。

### 4. 创建交付快照

在“交付与归档”创建正式快照，查看纳入和排除明细，再生成 CSV 与 ZIP。导出引用同一份快照；之后的新补交不会改变已经生成的交付包。

## 体验提交者路径

使用种子生成的提交者凭证打开提交页面：

1. 填写姓名、学号等身份字段；
2. 上传材料并保存服务器草稿；
3. 检查缺项和条件材料；
4. 正式提交并查看回执；
5. 根据组织者的补正要求上传新版本。

上传只表示文件已收到，正式提交才会生成可审核版本。刷新页面可以恢复服务器草稿；并发编辑冲突会保留当前填写内容，并要求先重新加载最新草稿。

## 查看 Agent 边界

FormFlow 把 Agent 能力放在明确的运行边界内：

- Skill 固化资料提取、规则编译、证据引用和输出格式；
- Harness 限制任务范围、工具白名单、预算、超时、重试和人工接管；
- MCP sidecar 只提供任务列表、收集汇总、下一步路线和 runtime 合同等只读信息；
- 确定性检查由程序完成，模型负责理解、比对和解释。

文件审核优先使用部署者配置的 provider 的 PDF 或图片输入。provider 不支持、文件超限或调用失败时，系统才进入文字解析或 OCR 降级；`direct` 模式会报告失败，不会偷偷切换到 OCR。模型密钥只由部署者保存在本地 `.env`、进程环境或部署平台 Secret 中，不写入数据库、浏览器、日志或审计事件。

网页内置 Agent 不直接连接外部 MCP。需要检查 MCP 协议时，可在第二个终端运行：

```bash
FORMFLOW_DEMO_PASSWORD=demo1234 python scripts/demo_mcp.py --non-interactive --task-id 1
```

PowerShell：

```powershell
$env:FORMFLOW_DEMO_PASSWORD = 'demo1234'
python scripts/demo_mcp.py --non-interactive --task-id 1
```

该脚本只调用四个只读工具，不读取逐人材料正文，也不写入业务数据。

## 自动化检查

展示验收脚本覆盖桌面、390px 和 320px 视口、主要入口、无效编号、失败态、横向溢出和浏览器错误：

```bash
FORMFLOW_SHOWCASE_BASE=http://127.0.0.1:8000 node scripts/showcase_check.cjs
```

需要复跑完整浏览器路径时，在隔离演示库安装 Playwright 与 Chromium 后运行对应的 `scripts/ux_*.cjs`。这些脚本可能创建任务或改变演示状态，不要连接真实业务库。

## 故障与恢复

新语义检查需要 Worker 和模型配置；没有模型密钥时，材料仍会被保存，检查显示“未完成”并转人工处理。诊断日志位于 `data/demo/logs/api.log` 和 `data/demo/logs/worker.log`。恢复初始演示数据前确认使用的是独立演示目录，再运行 `python scripts/start_demo.py --reset`。

演示备份可以使用 `python scripts/backup_demo.py create` 创建，并用 `python scripts/backup_demo.py verify <备份文件>` 校验。备份未加密，只适合虚构演示数据的本地恢复演练。
