## 如何阅读

每份记录都应说明四件事：

1. **场景**：使用什么数据、设备和配置。
2. **结论**：用户完成了什么，哪些结果需要人工接手。
3. **证据**：截图、脚本、自动化报告或复现命令。
4. **限制**：没有覆盖的 provider、材料、设备或安全条件。

日期、端口、提交号和测试数量只用于定位原始环境。记录中的“通过”只表示指定场景完成验证，不代表真实模型质量、屏幕阅读器体验或公网部署已经验收。

## 新增记录

新增记录沿用上述四段结构，标题直接描述场景和用户价值。实现过程、个人汇报、未验证推测和未来计划应放在对应的代码提交、路线图或问题记录中，不混入验证结论。
