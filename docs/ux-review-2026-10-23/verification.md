## 走查确认正常的部分

- 登录页：组织者 / 提交者两个页签、「体验演示环境」一键进入、演示账号提示都在。
- 任务列表：统计卡与筛选一致，空态文案可用。
- 收集工作台：应交 / 免交 / 已提交 / 已验收分开统计，「下一步」提示条指向具体的人，催交面板会说明「已提交、免交、已过截止的不再催交」。
- 需求设计台：蓝图、规则、时间策略、发布前核对都能正常渲染；无密钥时有常驻提示条。
- 名单与凭证：5 人名单、已发放 / 免交 / 待发放统计自洽；重发凭证会提示「同名主体仅提示待核，不自动合并」。
- 证据复核：按提交者逐条列出规则结论、原文位置与覆盖明细。
- 交付与归档：快照 → CSV + ZIP，排除原因逐条写明（当前版本未验收 / 无正式提交版本 / 有效免交不等于验收）。
- 提交者端：字段、材料槽位、回执、核对进度、补正入口齐全；上传 ≠ 正式提交有明确提示。
- 移动端 390px：登录、工作台、设计、复核、提交者页均无整页横向溢出。

## 关于一个看起来像 bug 的现象

给已存在的「赵六」发凭证时，接口一度返回了新的主体编号。复查后确认是走查时用 `curl -d` 直接塞中文、没做 URL 编码，
服务端按表单编码解析导致姓名对不上，于是按新主体处理。用 `--data-urlencode` 重测会正确复用原主体并返回「此前已有有效凭证」的提示。
浏览器提交表单本身是正确编码的，因此这不是产品缺陷，这里记一笔避免下次误判。
