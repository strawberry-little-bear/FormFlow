# 历史评审：收集与审核闭环

> 这是一份历史验证存档：记录指定版本、数据和环境下的用户可见结果。它不是产品介绍、开发日报或未来承诺。

**验证日期**：2026-10-23
**场景**：第一次打开作品的组织者与提交者
**数据**：虚构种子；未配置模型密钥
**性质**：体验证据存档，不是产品介绍或开发日报

## 结论

主要路径可以完成：组织者能够查看任务、设计要求、管理名单、复核提交和生成交付；提交者能够登录、填写、上传、查看回执并进入更正流程。无模型密钥时，页面会把模型不可用与业务不合格分开说明，材料仍然保留给人工处理。

## 用户可见结论

| 场景 | 用户影响 | 版本行为 |
| --- | --- | --- |
| 直接打开缺少提交者编号的复核地址 | 框架英文校验原文不能指导用户下一步 | 显示“先选一位提交者”空态，并保留返回工作台入口；框架话术单独翻译，业务错误原样保留 |
| 未配置模型密钥后提交需求 | 无效的“重试”会把用户带回必然失败的路径 | 区分“未配置密钥”和“本次响应失败”，提示先使用模板或手动草案，移除无效重试入口 |
| 浏览器标签页 | 缺少图标并产生 404 | 内联 SVG favicon |
| 登录页功能图标 | 字符图标与全站图标风格不一致 | 统一为 SVG 图标 |
| 日期、时区与提交回执 | 信息重复且站在系统视角描述提交时间 | 使用短日期格式，将“服务端时间”改为“提交时间” |
| CSV 收件时间 | UTC 原始串增加了交付后的换算成本 | 按任务时区导出可读时间；非法时区回退 UTC 并明确标注 |

## 已覆盖的路径

登录、任务列表、收集工作台、需求设计、名单与凭证、证据复核、交付归档和提交者页面均完成主要操作。应交、免交、已提交、已验收和排除原因分开呈现；390px 窄屏没有整页横向溢出。

## 限制与复现

材料、人物和结论均为虚构数据。空模型密钥只验证降级文案和人工接管，不代表真实模型质量。一次未进行 URL 编码的中文 `curl -d` 请求造成了同名新主体；使用正确表单编码后会复用原主体，因此该现象不属于浏览器产品缺陷。

复现脚本：`scripts/ux_walkthrough.cjs`、`scripts/ux_review_check.cjs`、`scripts/ux_submitter_check.cjs`、`scripts/ux_key_paths.cjs`。
