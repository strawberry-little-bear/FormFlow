# 验证档案：一次完整的收集与交付体验

> 这是一份面向访客的产品档案。它记录虚构数据、空模型密钥和指定浏览器视口中的可见行为，帮助读者理解 FormFlow 的主流程与恢复方式。

## 体验场景

组织者从任务设计开始，经过名单、收集工作台和证据复核，最后固定交付快照；提交者完成登录、填写、上传、正式提交和补正入口。页面把“已经收到”“检查未完成”“需要组织者确认”和“提交者需要修改”分开显示。

## 用户可见结果

| 入口 | FormFlow 呈现的结果 |
| --- | --- |
| 复核地址缺少提交者编号 | 给出“先选一位提交者”的空态，并提供返回工作台入口；框架校验话术转换为中文提示 |
| 未配置模型密钥后提交需求 | 保留已上传资料，提示使用模板或手动编辑草案；不提供必然失败的重复重试 |
| 浏览器标签页与登录页 | 使用统一的 SVG 图标，不产生 favicon 404 |
| 时间与提交回执 | 使用短日期格式，提交者看到“提交时间”，时区只在需要时出现 |
| CSV 收件时间 | 按任务时区导出可读时间；非法时区回退 UTC 并在导出中标明 |
| 审核未完成 | 显示为待处理或人工接管，不把模型不可用误报成材料不合格 |

## 主流程覆盖

组织者可以查看任务、设计要求、管理名单、复核提交并生成交付快照；提交者可以查看字段、材料槽位、回执和更正入口。应交、免交、已提交、已验收和排除原因分开呈现；桌面与 390px 视口没有整页横向溢出。

## 复现入口与边界

复现脚本包括 `scripts/ux_walkthrough.cjs`、`scripts/ux_review_check.cjs`、`scripts/ux_submitter_check.cjs` 和 `scripts/ux_key_paths.cjs`。材料、人物和结论均为虚构数据；空模型密钥只验证降级文案和人工接管，不代表真实模型质量。浏览器表单会正确编码中文，直接使用未编码的命令行表单不属于浏览器产品路径。
