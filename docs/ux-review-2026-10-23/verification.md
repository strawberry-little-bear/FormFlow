# 收集、审核与交付：可复现体验

这份档案展示第一次打开作品时，组织者和提交者各自能完成什么。数据为虚构种子，模型密钥留空，页面在桌面和 390px 浏览器中复现。

## 访客可以完成的事

组织者可以查看任务、设计要求、管理名单、复核提交并生成交付快照；提交者可以登录、填写、上传、查看回执并进入更正流程。模型不可用时，页面把“检查未完成”和“业务不合格”分开表达，材料仍可交给组织者处理。

## 用户可见结果

| 场景 | 结果 |
| --- | --- |
| 复核地址缺少提交者编号 | 显示“先选一位提交者”的空态，并提供返回工作台入口；框架校验话术已转为用户可读中文 |
| 未配置模型密钥后提交需求 | 明确提示先使用模板或手动草案，区分未配置密钥与本次响应失败，不提供必然失败的重试入口 |
| 浏览器标签页 | 使用内联 SVG favicon，不产生图标 404 |
| 登录页功能图标 | 与侧栏统一使用 SVG 图标 |
| 日期、时区与提交回执 | 使用短日期格式；用户看到“提交时间”，时区只在需要时出现 |
| CSV 收件时间 | 按任务时区导出可读时间；非法时区回退 UTC 并标明 |

## 覆盖范围与边界

登录、任务列表、收集工作台、需求设计、名单与凭证、证据复核、交付归档和提交者页面均覆盖主要操作。应交、免交、已提交、已验收和排除原因分开呈现；390px 窄屏没有整页横向溢出。

材料、人物和结论均为虚构数据。空模型密钥只验证降级文案和人工接管，不代表真实模型质量。未进行 URL 编码的中文命令行表单可能被服务端按新主体解析；浏览器表单编码路径不受影响。

**复现入口**：`scripts/ux_walkthrough.cjs`、`scripts/ux_review_check.cjs`、`scripts/ux_submitter_check.cjs`、`scripts/ux_key_paths.cjs`
