# 验证档案：展示模式的双角色讲解路径


> 这是一份历史验证存档：记录指定版本、数据和环境下的用户可见结果。它不是产品介绍、开发日报或未来承诺。

## 场景

展示模式需要让访客按清晰顺序了解组织者和提交者两条路径，同时尽快看到 Agent 运行状态和证据入口。窄屏下尤其需要减少重复说明，避免主路径被推到页面下方。

## 结果

| 访客动作 | 页面提供的线索 |
| --- | --- |
| 先看组织者路径 | 进入工作台，查看要求、名单、收集进度和证据复核 |
| 回看 Agent 运行证据 | 返回展示首页，查看运行阶段和只读 MCP 摘要 |
| 体验提交者路径 | 打开提交者回执，查看提交、补正和责任边界 |

展示模式隐藏重复的完整角色说明，普通任务页仍保留完整说明，保证演示路线和日常工作信息各自完整。

## 验证

- `node --test tests/frontend_contracts.test.cjs`：通过。
- `node --check app/static/app.js`：通过。
- `git diff --check`：通过。
- 演示服务：`python scripts/start_demo.py --reset` 启动成功，API 与 Worker 均就绪。
- 浏览器走查：1440 / 390 / 320px 展示模式均无控制台错误、无失败请求、无横向溢出；双角色入口链接、推荐顺序文案、Agent 控制面板和运行阶段均可见。
- 展示模式页面高度由隐藏重复角色说明而缩短；普通任务页未启用展示模式时仍渲染完整双角色说明。

## 边界

该档案验证展示路径的信息顺序和响应式呈现，不覆盖业务状态、权限、Agent 运行逻辑、真实模型、真实 MCP sidecar、屏幕阅读器或生产部署。
