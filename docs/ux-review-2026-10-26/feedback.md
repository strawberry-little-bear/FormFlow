# 评审记录：启动参数、异常入口与责任分工

这份记录用于复核 FormFlow 在三个容易卡住人的场景中的产品行为：自定义端口启动、无效路由加载失败，以及提交者查看检查结果。数据为虚构演示数据，模型密钥留空。

## 复核结果

| 场景 | 处理后的用户结果 | 责任归属 |
| --- | --- | --- |
| 使用 `--reset --port 8011` 启动 | 启动器检查传入的 8011；只有 8011 真被占用时才提示冲突，并显示实际端口号 | 启动者选择可用端口后重试 |
| 打开 `#/roster/9999` | 加载占位被替换为“任务不存在”的说明，并提供返回工作台入口 | 组织者选择有效任务 |
| 打开 `#/review/1/9999` | 显示“主体不存在”的失败状态，不遗留“正在读取检查结果…” | 组织者选择有效提交者 |
| 提交者查看已提交材料 | 可由提交者处理的缺项，与组织者核对、检查未完成和等待验收分开显示 | 提交者处理自己的事项，组织者完成确认 |

## 产品约定

错误页面必须说明原因并给出恢复入口。无效编号不能让页面永久停在加载中；检查未完成不能被写成提交者的不合格；组织者待办也不能被误标为提交者任务。

## 复现边界

记录只覆盖指定版本、虚构数据和本地浏览器。它验证页面状态和恢复路径，不代表真实 provider 的模型质量、敏感材料处理、生产并发或公网部署安全。
