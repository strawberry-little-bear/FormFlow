# 验证档案：收集、复核与交付

## 验证对象

这份档案展示 FormFlow 在虚构演示数据、未配置模型密钥和本地浏览器中的完整工作流。它面向第一次打开作品的访客，重点是组织者如何把资料变成任务、如何复核提交，以及如何生成可交付的归档包。

## 访客可以看到什么

| 场景 | 可见体验 | 责任边界 |
| --- | --- | --- |
| 登录与任务列表 | 进入组织者或提交者入口，看到任务、身份和待办 | 仅覆盖演示账号和虚构种子 |
| 收集工作台 | 按应交、免交、已提交和已验收分组，并定位下一步 | 组织者决定催交、补正和验收 |
| 需求设计 | 查看蓝图、规则、时间策略、来源资料和发布前核对 | 草案必须由组织者确认后发布 |
| 名单与凭证 | 查看名单、发放状态和重复主体提示 | 同名主体不会自动合并 |
| 证据复核 | 按提交者查看规则结论、原文位置和覆盖明细 | 模型引用是定位线索，最终判断由组织者完成 |
| 交付与归档 | 固定快照，生成 CSV 和 ZIP，并显示排除原因 | 只有符合当前验收条件的版本进入快照 |
| 提交者流程 | 填写字段、上传材料、保存草稿、正式提交、查看回执和补正 | 上传本身不等于正式提交 |

## 结果与边界

- 未配置模型密钥时，材料仍可接收；语义检查显示“未完成”，不会自动改判为材料不合格。
- 文件类型、数量、大小、时间和导出规则由确定性检查处理；内容理解、跨文件比对和排版判断保留 `unknown` 或 `failed` 状态，等待人工处理。
- 390px 和 320px 视口下，登录、工作台、设计、复核和提交者页面保持可用，没有整页横向溢出。
