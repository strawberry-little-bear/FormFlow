# 验证档案：启动、收件与复核体验

**场景**：组织者与提交者主要路径、启动器、复核、交付和窄屏布局
**环境**：虚构种子、未配置模型密钥、1440/390/320px 浏览器
**用途**：记录该环境下可复现的用户体验结果和待处理事项

## 用户可见结论

收件闭环可以完成：提交者能够登录、填写、上传、保存草稿、刷新恢复并正式提交；组织者能够进入工作台、复核和交付。模型不可用时，语义检查保持“未完成”，不会被显示成不合格。

## 待处理事项

| 优先级 | 场景 | 用户影响 | 建议方向 |
| --- | --- | --- | --- |
| P0 | Windows 中文环境下启动器复用 `tasklist` 的编码处理不稳定 | 第二次 `--check` 或 `--stop` 可能无法使用 | 使用系统编码读取进程列表，并保留可读失败信息 |
| P1 | 320px 提交者操作区拥挤 | 正式提交入口不容易发现 | 统一次要操作高度，调整窄屏操作顺序 |
| P2 | 复核页把“已满足”和“阻塞验收”放在相同视觉层级 | 结果状态与规则属性容易混淆 | 分开呈现结果状态和验收影响 |
| P2 | 凭证错误提示重复表达同一原因 | 信息像系统拼接 | 有后端 `detail` 时直接展示，前缀只作兜底 |
| P3 | ZIP 条目使用 1980-01-01 默认时间 | 交付包看起来像丢失时间信息 | 写入快照时间或原件时间 |
| P3 | 跨年截止时间缺少年份 | 用户需要自行推断日期 | 跨年时显示完整日期 |
| P3 | 复核页没有给出模型配置的下一步 | 用户知道原因但不知道如何处理 | 提供轻量配置说明入口 |

## 已覆盖

密码和凭证错误、无效任务与设计编号、重复上传、催交排除规则、快照导出、390/320px 横向溢出和基础键盘路径均有结果。后续版本以当前代码和更新后的验证档案为准。

## 限制

本档案只适用于指定版本、虚构数据和本地浏览器，不代表真实模型质量、真实材料处理、屏幕阅读器或公网部署已经验收。
