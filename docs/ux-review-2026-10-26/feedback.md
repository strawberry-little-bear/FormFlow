# 产品档案：启动参数与审核失败状态

这页描述 FormFlow 在四个容易打断流程的场景中的用户可见行为。读者可以用虚构演示数据、空模型密钥和本地浏览器复现；内容关注页面给出的信息和恢复入口，不记录开发过程。

## 访客看到的结果

| 场景 | 页面表现 | 可执行的下一步 |
| --- | --- | --- |
| 使用自定义端口启动 | 启动器检查并使用传入端口，错误提示与实际端口一致 | 修正占用端口后重新启动 |
| 打开无效名册路由 `#/roster/9999` | 加载占位被替换为任务不存在的失败态，并提供返回工作台入口 | 返回有效任务或重新选择任务 |
| 打开无效复核路由 `#/review/1/9999` | 加载占位被替换为主体不存在的失败态，不再与错误提示并排卡住 | 选择有效提交者，或回到工作台 |
| 提交者看到审核结果 | “需要你处理”和“需要组织者确认”分开显示；模型未完成不会变成提交者待办 | 处理可操作项，或等待组织者确认 |

## 设计边界

失败状态说明发生了什么、影响哪一步以及从哪里恢复。接口失败后页面不保留加载占位；组织者待办不会被写成提交者可以完成的动作。未配置模型、无效编号和暂时无法判断都回到人工可控的流程。
