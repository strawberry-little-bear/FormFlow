# 产品档案：错误入口也能继续完成任务

这页用四个常见入口说明 FormFlow 如何处理失败、缺失和等待状态。场景使用虚构演示数据，模型密钥留空；重点是用户能否理解当前状态，并找到下一步。

## 可见结果

| 场景 | 页面结果 | 下一步 |
| --- | --- | --- |
| 使用 `--reset --port 8011` 启动 | 启动器检查传入的 8011；只有 8011 确实被占用时才提示冲突，并显示实际端口号 | 选择可用端口后重新启动 |
| 打开 `#/roster/9999` | 加载占位被替换为“任务不存在”，同时提供返回工作台入口 | 选择有效任务 |
| 打开 `#/review/1/9999` | 显示“主体不存在”的失败状态，不遗留“正在读取检查结果…” | 选择有效提交者 |
| 提交者查看检查结果 | 提交者能处理的缺项，与组织者核对、检查未完成和等待验收分开显示 | 提交者修改材料；组织者完成确认 |

## 责任分工

FormFlow 的异常状态需要回答两个问题：发生了什么，接下来能做什么。无效编号不会让页面永久停在加载中；检查尚未完成不会被写成提交者不合格；组织者待办也不会伪装成提交者任务。

提交者只看到自己能修改的缺项；组织者待办、检查未完成和等待验收会单独显示。失败原因会保留下来，用户可以从工作台回到正确的任务或主体继续处理。

## 复现范围

截图、运行条件和浏览器脚本位于本目录。档案只覆盖指定版本、虚构数据和本地浏览器中的恢复行为；真实 provider、敏感材料、生产并发和公网部署需要在授权环境中单独验收。
