# 验证档案：从收集要求到交付归档

这份档案用虚构演示数据展示 FormFlow 的主产品路径。访客可以看到资料如何变成任务、材料如何进入审核、证据如何回到原文，以及组织者如何固定交付快照。

## 访客路径

| 场景 | 访客看到的结果 | 谁负责下一步 |
| --- | --- | --- |
| 登录与任务列表 | 组织者和提交者从各自入口进入，看到任务、身份和待办 | 账号持有人选择入口 |
| 收集工作台 | 应交、免交、已提交和已验收分组清晰，下一步动作指向具体提交者 | 组织者催交、补正和验收 |
| 需求设计 | 蓝图、规则、时间策略、来源资料和发布前核对集中呈现 | 组织者确认后发布 |
| 名单与凭证 | 名单、发放状态和重复主体提示可追溯 | 组织者处理凭证与主体核对 |
| 证据复核 | 每条规则都有结论、解释、文件和页码位置 | 组织者核对原文并决定是否验收 |
| 交付与归档 | 快照、CSV、ZIP 和排除原因来自同一份已确认状态 | 组织者固定交付版本 |
| 提交者流程 | 字段、材料、草稿、正式提交、回执和补正入口连成一条路径 | 提交者处理自己的问题 |

## 可信边界

- 未配置模型密钥时，材料仍能被接收；语义检查显示“检查未完成”，不会自动改判为不合格。
- 文件类型、数量、大小、时间和导出条件由程序检查；内容理解、跨文件比对和排版判断可以停在“证据不足”或“需要人工处理”。
- 模型返回的文件和页码是定位线索，程序会校验引用格式，但最终判断仍由组织者打开原文完成。
- 390px 和 320px 视口下，登录、工作台、设计、复核和提交者页面保持可用，没有整页横向溢出。
