# 场景档案：从异常入口回到可继续的任务

FormFlow 把错误入口、端口冲突和未完成检查都变成可理解的产品状态。用户能看到发生了什么，也能直接找到下一步，而不会被框架原文或永久加载占住。

## 用户能看到什么

| 场景 | 页面结果 | 可执行动作 |
| --- | --- | --- |
| 使用 `--reset --port 8011` 启动 | 启动器检查传入的 8011，并在真实占用时显示实际端口 | 更换可用端口后重新启动 |
| 打开 `#/roster/9999` | 加载占位被替换为“任务不存在” | 返回工作台并选择有效任务 |
| 打开 `#/review/1/9999` | 显示“主体不存在或不属于该任务”，不再遗留加载文字 | 返回任务并选择有效提交者 |
| 提交者查看尚未完成的检查 | 可修改的事项与组织者待办、等待验收和检查失败分开显示 | 提交者修改材料，组织者完成确认或重新发起检查 |

## 产品行为

错误提示包含对象、状态和下一步入口。无效编号会离开加载态；检查未完成会保持“尚未形成结论”的语义，不会被误报为材料不合格；提交者不会被要求处理只能由组织者完成的事项。

## 复现边界

截图、运行条件和浏览器脚本位于本目录。该场景使用虚构数据和本地浏览器，覆盖的是页面恢复行为；真实 provider、敏感材料、生产并发和公网部署仍需在授权环境中单独验收。
