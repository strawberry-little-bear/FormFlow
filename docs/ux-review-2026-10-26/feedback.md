# 验证档案：启动、收件与复核体验

这份历史记录用于说明一次完整的本地体验检查。它覆盖组织者与提交者主要路径、启动器、证据复核、交付和窄屏布局；数据为虚构种子，模型密钥为空，浏览器视口为 1440px、390px 和 320px。

## 用户可完成的路径

提交者可以登录、填写字段、上传材料、保存服务器草稿、刷新恢复并正式提交。组织者可以进入工作台、查看收集进度、打开复核结果并生成交付快照。模型不可用时，语义检查保留为“未完成”，材料仍可交给人工处理，不会被显示成不合格。

## 当时记录的问题

| 优先级 | 用户看到的现象 | 影响 | 后续处理方向 |
| --- | --- | --- | --- |
| P0 | Windows 中文环境下启动器复用 `tasklist` 时编码处理不稳定 | 第二次 `--check` 或 `--stop` 可能无法使用 | 使用系统编码读取进程列表，并保留可读失败信息 |
| P1 | 320px 下提交者操作区拥挤 | 正式提交入口不容易发现 | 统一次要操作高度，调整窄屏操作顺序 |
| P2 | 复核页把“已满足”和“阻塞验收”放在相同视觉层级 | 结果状态和验收影响容易混淆 | 分开呈现检查结果与验收属性 |
| P2 | 凭证错误提示重复表达同一原因 | 信息像系统拼接 | 后端已有 `detail` 时直接展示，前缀只作兜底 |
| P3 | ZIP 条目使用 1980-01-01 默认时间 | 交付包看起来像丢失时间信息 | 写入快照时间或原件时间 |
| P3 | 跨年截止时间缺少年份 | 用户需要自行推断日期 | 跨年时显示完整日期 |
| P3 | 复核页没有给出模型配置的下一步 | 用户知道原因但不知道如何处理 | 提供轻量配置说明入口 |

## 已覆盖的行为

密码和凭证错误、无效任务与设计编号、重复上传、催交排除规则、快照导出、390/320px 横向溢出和基础键盘路径均有结果。后续代码版本以最新验证档案和当前测试为准。

## 验证限制

记录只适用于上述版本、虚构数据和本地浏览器。它不代表真实模型质量、真实材料处理、屏幕阅读器体验或公网部署已经验收。
