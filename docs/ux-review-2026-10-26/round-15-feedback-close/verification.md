# 验证档案：评审反馈对应的用户结果

这份档案把一组常见演示场景放回用户路径中，展示访客可以直接观察到的结果。它不按开发顺序叙述工作，而是按“遇到什么场景、页面给出什么反馈、谁继续处理”来组织证据。

## 场景与结果

| 场景 | 用户看到的结果 |
| --- | --- |
| Windows 启动器读取 `tasklist.exe` | 兼容本地代码页和 bytes fallback，中文系统不会因编码异常中断 |
| 提交者在 390px 或 320px 视口正式提交 | 主按钮保持整行，文字不溢出，页面没有横向滚动 |
| 组织者查看已满足规则 | 已满足、不适用和已人工解决的规则不再显示为当前阻塞项，证据详情保留来源说明 |
| 凭证接口返回已有业务错误 | 页面直接展示业务提示，不重复拼接通用前缀 |
| 导出包含材料的 ZIP | 条目使用提交快照时间，不回落到 ZIP 默认的 1980-01-01 |
| 查看截止时间 | 日期包含年份，任务时区在独立信息中展示 |
| 没有模型密钥时打开复核 | 材料仍可保存；检查明确标记为未完成，并引导使用模板或手动处理，不提供无效重试 |

## 复现信息

专项 Python 测试、前端契约、JavaScript 语法检查和 `git diff --check` 覆盖了上述行为；隔离浏览器复现了无效主体、移动端提交和已满足规则的证据详情，截图保存在本目录的 `round-25-browser/`。

## 边界

本档案没有进行真实屏幕阅读器测试、真实用户试点或真实 provider 质量评估。演示种子使用离线脚本，模型服务的准确率和生产部署安全需要单独验收。
