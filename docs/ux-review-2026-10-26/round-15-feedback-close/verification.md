# 短期评审反馈闭环记录

日期：2026-10-26

本记录对应 `docs/ux-review-2026-10-26/feedback.md` 中列出的短期评审反馈。原反馈文档说明“本轮只记录、不修复”是当时走查的记录范围；本轮依据后续工作指令完成修复与回归确认。

## 反馈处理结果

1. **Windows 一键启动脚本的 `tasklist.exe` 编码异常**

   已确认修复。`scripts/start_demo.py` 对 Windows 输出使用本地编码兼容路径，并保留替换字符与 bytes fallback；`--check` 不再因中文系统的 GBK 输出触发 `UnicodeDecodeError` 或随后出现的 `None.splitlines()`。

2. **提交者移动端正式提交操作区拥挤**

   已确认修复。真实浏览器检查了 390px 和 320px 视口：正式提交按钮保持整行主按钮，文字不溢出，操作区没有整页横向滚动。

3. **复核页“已满足”规则同时显示“阻塞验收”**

   已确认修复。规则列表与证据详情都不再把已满足、不适用或已被人工解决的规则显示为当前“阻塞验收”状态；待人工、有问题、检查未完成的规则仍保留严重度信息。点击已满足规则后的真实证据详情显示“程序校验 / 可自动检查 / 来源”，不再出现“阻塞验收”。

4. **凭证错误提示重复**

   已确认修复。后端已有明确业务错误时，前端直接展示业务错误；只有缺少具体错误时才使用通用兜底前缀，避免“凭证无效或已失效：凭证无效或已撤销”的重复文案。

5. **导出 ZIP 材料时间戳回落到 1980-01-01**

   已确认修复。材料条目写入 ZIP 时使用快照时间构造 `ZipInfo`，导出的材料时间与提交快照保持一致，不再使用 ZIP 默认纪元时间。

6. **截止时间卡片缺少年份**

   已确认修复。提交者页面的截止时间与补正截止时间显示完整日期和年份；任务时区在独立的“时区”信息中展示，避免跨年任务产生歧义。

7. **无模型密钥时复核页缺少下一步引导**

   已确认修复。语义检查未完成时，失败规则详情会明确说明需要配置 `FORMFLOW_LLM_API_KEY`；页面同时保留“先用模板或手动改草案，配置密钥后再发起检查”的处理路径，并移除不会成功的“用原请求重试”动作。该路径通过前端契约和代码路径验证；本轮演示种子使用 `ScriptedLLM`，因此没有自然产生模型失败规则。
