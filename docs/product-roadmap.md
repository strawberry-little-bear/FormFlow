# 从可演示原型到适合人用的 FormFlow

更新：2026-10-21。依据产品方案 v0.3；这是后续设计与验收路线，不代表所有条目已经实现。

## 产品主张与不做什么

围绕一个收集任务提供完整闭环：要求 → 收件 → 有证据的补正 → 人工验收 → 正确版本交付。先验证团课材料场景，再验证团队比赛报名的复用性。不扩展成通用流程引擎，不做文章打分、真实性认定或 AI 写作检测。

判断一次迭代是否值得做：**它是否减少一次找入口、猜状态、重复填写或拿错版本？** 不以多一个聊天窗口或多一张统计图作为完成标准。

## 当前已落地

- 五个工作区贯通：需求设计、名单与凭证、收集工作台、证据复核、交付与归档；提交者有独立填写/回执/结果入口。
- 设计输入恢复、发布差异与基线冲突保护；提交缺项定位、草稿并发保护、不可变正式版本；规则证据、申诉、人工决定、独立资格与免交生命周期；固定快照 CSV/ZIP。
- 本轮补齐：三类复核理由刷新恢复、账号/主体/版本/成员/运行隔离、后端复核范围前置校验、晚响应不清新输入、材料/资格/验收导航、下一待处理与“只看待处理”规则筛选。
- 能力由自动化回归及局部浏览器验收支持，**尚无真实用户收益或准确率证据**；详见本轮 verification。

### 真实试走脚本（先虚构或授权脱敏材料）

招募组织者与提交者分别完成：建立任务并解释要求、收到邀请后提交、读懂补正并更新、人工判断与验收、下载正确交付包。记录每个卡点、误点、打开原文件次数、处理时长及机器意见被纠正的原因，不预设“节约多少”。失败也必须记录。

## P2：韧性、可达性和评估

- 逐页键盘/读屏检查：焦点恢复、错误摘要、弹窗关闭、状态播报频率；320/390/768px、长任务名/文件名、200%缩放、低网速/断网不遮挡关键操作。
- 三类草稿明确本地/服务器/正式版本边界，考虑主动保存复核草稿到服务器的独立产品需求；未经确认不把敏感未提交意见跨设备同步。
- 授权样本评估：可定位引用、问题漏报/误报、不可读区域、注入、预算耗尽；按规则/文件类型分组，记录人工修正成本。先定义阈值再评估，不从演示种子推导准确率。
- 清理依赖弃用和外键环警告，锁定可重复依赖、CI回归与备份恢复演练；多 Worker 前先建立领取锁/租约，不能直接多进程重复执行。

## 上线前必经门槛（尚未完成）

1. 真实材料处理的告知、授权、留存、删除/恢复与模型供应商数据边界。
2. 公网鉴权/限流、会话与凭证策略、文件隔离和恶意内容扫描、资源上限、审计与告警。
3. 数据库及私有附件一致备份、恢复验证、部署/迁移回滚；历史免交歧义不能自动猜测。
4. 目标用户试点、可达性回归、模型质量与失败成本评估；有问题时可转人工。
5. 明确许可证与第三方依赖许可。未声明授权前不自称 MIT。

## 协作约束

仅在 main 开发。开始及提交前 fetch，安全整合；不覆盖其他人的未提交修改或资料、不强推。报告同时给出：完成了什么、以什么方式验证、什么仍未覆盖。后续路线不计入本轮完成范围，也不把原型称为生产可用系统。
