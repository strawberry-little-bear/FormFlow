# FormFlow 产品路线图

这份文档描述 FormFlow 当前的能力地图、下一阶段重点和验证边界。它面向维护者和评审者，不记录逐日开发过程；具体走查证据请看[走查证据索引](ux-review-index.md)。

## 当前产品形态

FormFlow 已经形成一条可展示的材料收集与审核闭环：组织者整理要求、发布任务、发放凭证，提交者填写并提交材料，审核 Agent 按规则给出逐项结论，组织者完成人工验收并导出交付快照。

当前最有辨识度的能力是：

- 需求 Agent 把通知、名单、模板和附件说明整理成可确认蓝图；
- 审核 Agent 在表单和多份材料之间做一致性核验，并保留证据位置；
- Skill 固化 Agent 的方法和输出格式；
- Harness 约束工具、预算、运行状态和恢复行为；
- MCP 提供受限的只读运行上下文；
- 文件输入优先走用户配置的模型原始文件能力，必要时才使用文字解析或 OCR 降级；
- 组织者保留发布、补正、验收和交付决定。

## 当前重点

### 1. 来源资料的可追溯管理

设计台已经支持上传通知、名单、模板和附件资料。系统保存原始文件、解析状态、来源 ID 和摘要；需求 Agent 只能引用已登记的来源，并在蓝图中保留资料定位。解析失败时保留明确状态，由组织者决定是否继续。下一步是补充来源替换、删除、版本化和差异比较。

### 2. 跨文件审核的证据质量

“姓名/学号表单 + 多份报名材料”已经是审核 Agent 的标准场景，能够展示字段一致性、规则覆盖、证据定位和补正建议。下一步是增加页级预览、结构化格式检查和更可靠的证据回链。无法确认的内容进入 `unknown` 或人工处理，不被压成一个模糊的“未通过”。

### 3. 模型配置与数据边界

部署者已经可以在本地配置 provider、模型和输入模式。应用不保存 API Key，也不把密钥写入审计或返回给浏览器；界面明确提示哪些材料会发送给外部 provider，哪些检查由本地程序完成。后续将继续补充 provider 兼容性检查、调用预算和失败回退的可视化状态。

### 4. 评估与回归

仓库已经包含脱敏评估集、浏览器 Showcase Harness，以及针对权限、版本、恢复和证据引用的自动化测试。后续继续扩充跨文件规则和真实 provider 适配案例；所有结果都区分演示种子、合成测试和真实授权数据。

## 后续方向

| 方向 | 目标 |
| --- | --- |
| 来源资料管理 | 支持替换、删除、版本化和来源差异比较 |
| 审核工具 | 增加页级预览、结构化格式检查和更可靠的证据回链 |
| 组织者工作台 | 让筛选、催交、补正和验收动作围绕“下一步”组织 |
| 提交者体验 | 强化条件材料、弱网恢复、可访问性和多轮更正 |
| 生产部署 | 共享数据库、队列租约、对象存储、备份恢复和审计保留策略 |
| 质量评估 | 在获准脱敏材料上建立按场景、规则类型和文件类型的阈值 |

## 验证边界

虚构种子只能验证流程和程序不变量，不能证明真实模型准确率。真实 provider 的文件输入、模型质量、敏感材料处理、屏幕阅读器、移动设备和公网安全都需要在授权环境中单独验收。
