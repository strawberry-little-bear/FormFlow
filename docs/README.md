## 产品主线

需求 Agent 从通知、名单、模板和补充说明中提取字段、材料槽位、时间策略和审核规则，组织者确认蓝图后发布任务。提交者填写身份信息、上传材料、保存草稿并正式提交。审核 Agent 对照已发布规则比较表单、名单和多份材料，逐条输出 `satisfied`、`issue`、`unknown` 或 `failed`，并把证据位置与责任归属放在结果旁边。

确定性程序处理文件和状态约束，模型负责理解、比较和解释。Skill 固定 Agent 的工作步骤与输出格式，Harness 约束范围、工具、预算、超时和人工接管，MCP 提供受限的只读运行信息。API Key 只由部署者保存在本地配置或部署平台 Secret 中，不进入数据库、响应、日志或 MCP。

## 如何阅读产品档案

`ux-review-*` 目录是产品档案。每页围绕一个场景说明入口、数据、用户看到的结果、复现方法和覆盖边界。目录名中的日期和轮次只用于定位记录，不代表产品路线或完成承诺。

根目录 [README](../README.md) 负责说明产品；本页负责导航；[体验指南](demo-guide.md) 负责操作；证据档案负责复核具体行为。虚构种子和离线轨迹可以验证流程和界面，真实 provider、敏感材料和公网部署仍需在获准环境中单独验收。
