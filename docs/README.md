FormFlow 的需求 Agent 将通知、名单、模板和补充说明整理为可确认的收集蓝图；审核 Agent 按已发布规则检查表单和多份材料。确定性程序负责文件、字段和状态约束，模型负责理解、比对和解释，组织者负责确认冲突、处理不确定结果并决定是否验收。

## Agent 如何受控运行

文件审核优先使用部署者配置的 provider 的 PDF 或图片输入。provider 不支持、文件超限或调用失败时，才进入文字解析或 OCR 降级。结果会区分 `satisfied`、`issue`、`unknown` 和 `failed`，不会把证据不足写成不合格。

Skill 固化 Agent 的步骤、工具边界和输出格式；Harness 负责范围、预算、超时、重试、幂等和人工接管；MCP 只提供受限的只读运行信息。API Key 只在部署者自己的环境、`.env` 或部署平台 Secret 中配置，不进入数据库、响应、日志、审计事件或 MCP。

## 如何看产品证据

每份档案都从一个具体用户场景开始，说明使用的数据、入口、页面结果、复现脚本和限制。它面向访客展示产品行为，不记录个人开发过程；日期与轮次只用于定位版本和场景。

## 阅读顺序

根目录 [README](../README.md) 介绍 FormFlow 解决的问题和核心流程；本页负责导航；体验指南说明如何操作；产品证据展示页面行为、复现入口和边界。不同文档各自承担一个阅读任务，打开后可以直接找到下一步。
