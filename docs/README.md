# FormFlow 文档

FormFlow 把“整理要求、收集材料、逐项核验、交付归档”放在一条可追溯的流程里。下面按阅读目的安排入口，第一次了解作品可以直接从体验指南开始，不需要先翻历史记录。

## 先体验作品

| 入口 | 你会看到什么 |
| --- | --- |
| [体验指南](demo-guide.md) | 组织者和提交者各走一遍完整路径，从资料进入需求 Agent 到生成交付快照 |
| [交互设计说明](interaction-optimization.md) | 页面如何表达状态、证据、责任分工和人工接管 |
| [验证档案索引](ux-review-index.md) | 截图、浏览器脚本、运行条件和已知边界 |

## 接入和部署

| 入口 | 适合谁 |
| --- | --- |
| [部署与模型接入](deployment.md) | 需要启动服务、配置 provider 或设置本地 API Key 的部署者 |
| [审核 Agent 评估集](review-agent-evaluation.md) | 需要在获准脱敏材料上评估结论和证据覆盖的评估者 |
| [产品状态与方向](product-roadmap.md) | 想了解作品已经覆盖的场景和上线前仍需验证的部分 |

文件审核优先将原始 PDF 或图片交给部署者选择的模型；只有 provider 不支持、文件超限或调用失败时才进入文字解析/OCR 降级。API Key 只由部署者在本地配置，不会进入数据库、浏览器响应、日志、审计或 MCP。

## 推荐阅读的验证档案

- [完整收集、复核与交付](ux-review-2026-10-23/verification.md)：从组织者发布到提交者交件，再到证据复核和归档。
- [来源资料到需求 Agent](ux-review-2026-11-06-requirements-agent/verification.md)：通知、名单和模板怎样形成可编辑蓝图。
- [启动参数与失败状态](ux-review-2026-10-26b/feedback.md)：自定义端口、无效路由和责任分工的恢复路径。
- [展示与提交者闭环](ux-review-2026-11-04/verification.md)：展示模式、提交和补正入口。

验证档案是公开的产品证据。每份档案都从一个具体场景开始，接着说明可见结果、复现入口和适用边界；日期、提交号和测试数量只用于定位环境。档案中的“通过”表示指定环境下的行为已经核对，不代表真实模型质量、屏幕阅读器体验或公网部署已经验收。

完整的产品介绍以根目录 [README](../README.md) 为准。
