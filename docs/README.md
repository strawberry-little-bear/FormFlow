# FormFlow 文档

FormFlow 是一个可以现场演示的材料收集与审核工作流。下面按阅读目的提供入口，第一次了解作品不需要先读历史记录。

## 先体验

| 入口 | 适合谁 | 能看到什么 |
| --- | --- | --- |
| [体验指南](demo-guide.md) | 第一次打开作品的人 | 组织者和提交者各走一遍完整流程 |
| [交互设计说明](interaction-optimization.md) | 想了解产品判断的人 | 状态、证据、责任分工和人工接管 |
| [验证档案索引](ux-review-index.md) | 想核对实现的人 | 截图、脚本、环境和已知边界 |

## 部署和模型

| 入口 | 用途 |
| --- | --- |
| [部署与模型接入](deployment.md) | 启动服务、配置 provider、设置 API Key 和输入模式 |
| [审核 Agent 评估集](review-agent-evaluation.md) | 在获准的脱敏材料上评估结论和证据覆盖 |
| [产品状态与方向](product-roadmap.md) | 查看当前可展示能力和上线前门槛 |

FormFlow 优先将原始 PDF 或图片交给部署者选择的模型；只有 provider 不支持、文件超限或调用失败时才进入文字解析/OCR 降级。API Key 只由部署者在本地配置，FormFlow 不写入数据库、浏览器响应、日志、审计或 MCP。

## 推荐验证场景

- [完整收集、复核与交付](ux-review-2026-10-23/verification.md)：从组织者发布到提交者交件，再到证据复核和归档。
- [来源资料到需求 Agent](ux-review-2026-11-06-requirements-agent/verification.md)：通知、名单和模板如何形成可编辑蓝图。
- [启动参数与失败状态](ux-review-2026-10-26b/feedback.md)：自定义端口、无效路由和责任分工的恢复路径。
- [展示与提交者闭环](ux-review-2026-11-04/verification.md)：展示模式、提交和补正入口。

历史验证档案是公开的产品证据，不是开发日报。每份档案都按“场景、结果、复现、边界”组织；日期、提交号、端口和测试数量只用于复现定位。档案中的“通过”只表示指定环境下的行为已核对，不代表真实模型质量、屏幕阅读器体验或公网部署已经验收。

完整产品介绍以根目录 [README](../README.md) 为准。
