## 作品如何工作

FormFlow 先把通知、名单、模板和补充说明整理成收集蓝图，再把提交者的字段和多份材料交给审核流程。确定性检查负责文件和字段约束；Agent 负责理解、比对和解释；组织者负责确认冲突、处理不确定结果并决定是否验收。

文件审核优先使用部署者配置的 provider 的 PDF 或图片输入。provider 不支持、文件超限或调用失败时，才进入文字解析或 OCR 降级。结果会区分 `satisfied`、`issue`、`unknown` 和 `failed`，不会把证据不足写成不合格。

Skill 固化 Agent 的步骤、工具边界和输出格式；Harness 负责范围、预算、超时、重试、幂等和人工接管；MCP 只提供受限的只读运行信息。API Key 只在部署者自己的环境、`.env` 或部署平台 Secret 中配置，不进入数据库、响应、日志、审计事件或 MCP。

## 如何阅读验证档案

每份档案都从一个具体用户场景开始，说明使用的数据、入口、页面结果、复现脚本和限制。档案按用户能看到的结果组织内容，并保留可以复查的证据；日期与轮次只是归档编号，不代表开发进度或未完成事项。

## 阅读方式

根目录 [README](../README.md) 是作品介绍，说明 FormFlow 为谁解决什么问题；本页是文档导航；体验指南说明如何操作；验证档案提供产品证据。验证档案按用户场景命名和归档，保留运行条件、脚本、截图位置和已知边界，不把评审过程写成面向访客的产品叙事。

虚构种子和离线轨迹可以验证流程、权限、状态和导出行为，不能替代真实 provider 的质量评估、敏感材料处理、屏幕阅读器测试或公网部署验收。
