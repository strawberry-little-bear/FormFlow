# 产品档案：异常入口的恢复路径

这份档案展示 FormFlow 在启动端口、无效地址和审核状态异常时，如何把用户带回可继续的任务路径。数据为虚构演示数据，模型密钥留空；页面结果用于说明交互行为，不代表真实 provider 或生产环境验收。

| 场景 | 用户看到的结果 | 可执行的下一步 |
| --- | --- | --- |
| `--reset --port 8011` | 启动器检查 8011，并报告真实的端口冲突 | 选择可用端口后重试 |
| `#/roster/9999` | 任务不存在、返回入口和重新加载动作 | 选择有效任务 |
| `#/review/1/9999` | 主体不存在，加载占位被清除 | 选择有效提交者 |
| 提交者检查结果 | 自己能处理的缺项与组织者待办分开显示 | 提交者改材料，组织者做确认 |

## 设计要点

错误提示会说清实际对象和状态，并提供返回或重试入口。检查尚未完成时，页面保留“待处理”语义，不把它误报成材料不合格；提交者能处理的事项与组织者确认事项分开显示。

截图、运行条件和浏览器脚本位于本目录。档案覆盖虚构数据和本地浏览器中的恢复行为；真实模型输入、敏感材料处理、生产并发和公网部署仍需在授权环境中单独验收。
