# 体验记录：启动参数与失败状态

这份记录关注启动器端口、无效路由、展示入口、提交者进度、交付和复核页的失败状态。场景使用虚构种子且未配置模型密钥，重点是确认用户在失败时能看到原因和下一步。

## 关键结果

| 场景 | 用户可见结果 |
| --- | --- |
| 自定义端口 | 启动器检查并启动用户传入的端口，错误信息与实际端口一致。 |
| 无效名册路由 | `#/roster/9999` 会替换加载占位，说明任务不存在并提供返回工作台入口；无效任务不能继续导入。 |
| 无效复核路由 | `#/review/1/9999` 清除加载占位，只保留主体不存在的错误状态和返回入口。 |
| 提交者进度 | 提交者补正项与组织者待确认项分开显示，不会把模型未完成或组织者核对伪装成提交者待办。 |

## 仍需关注的细节

展示登录后的任务列表需要在更早位置出现；320px 下“重新加载服务器草稿”仍需要保持完整可读；交付页和复核页的重复入口与统计口径需要继续收敛；设计页左栏后半段可以增加更清晰的内容层次。

## 记录边界

结论只描述指定版本、虚构数据和本地浏览器中的体验现象，不替代当前代码回归，也不代表真实模型、真实材料或公网部署已经验收。
