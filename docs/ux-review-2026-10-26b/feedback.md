# 验证档案：启动参数与失败状态

## 验证对象

这份档案聚焦演示环境中最容易打断首次体验的四类状态：自定义端口启动、无效名册路由、无效复核路由，以及提交者与组织者的责任提示。结果来自虚构种子、未配置模型密钥和本地浏览器。

## 访客可以看到什么

| 场景 | 可见结果 |
| --- | --- |
| 自定义端口 | 启动器检查并启动用户传入的端口，错误提示与实际端口一致。 |
| 无效名册路由 | `#/roster/9999` 清除加载占位，说明任务不存在，并提供返回工作台入口。 |
| 无效复核路由 | `#/review/1/9999` 清除加载占位，只保留主体不存在的错误状态和返回入口。 |
| 提交者进度 | 提交者补正项与组织者待确认项分开显示；模型未完成或组织者核对不会伪装成提交者待办。 |

## 为什么这些状态重要

错误页面需要告诉访客发生了什么以及下一步能做什么；加载占位不能在接口已经失败后继续停留；责任提示必须让提交者知道哪些事项可以自己处理、哪些事项只能等待组织者。上述状态都在页面中保持可见且可恢复。

## 复现入口与边界

本目录保存对应截图和复现脚本。结论只适用于指定版本、虚构数据和本地浏览器，不代表真实模型、真实材料处理或公网部署已经验收。
