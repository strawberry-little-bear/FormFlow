# 产品证据：三条恢复路径

下面三条路径展示 FormFlow 如何把异常入口接回主流程。场景使用虚构演示数据和空模型密钥，用于快速了解错误提示、加载失败和责任分工的可见行为。

| 入口 | 用户看到的结果 | 可执行的下一步 |
| --- | --- | --- |
| `--reset --port 8011` | 启动器检查 8011，并报告真实的端口冲突 | 选择可用端口后重试 |
| `#/roster/9999` | 任务不存在、返回入口和重新加载动作 | 选择有效任务 |
| `#/review/1/9999` | 主体不存在，加载占位被清除 | 选择有效提交者 |
| 提交者检查结果 | 自己能处理的缺项与组织者待办分开显示 | 提交者改材料，组织者做确认 |

## 用户可见行为

错误提示会把端口、任务和主体的实际状态说清楚，并提供能恢复流程的入口；当检查尚未完成时，系统会保留“待处理”语义，不把它误报成材料不合格。提交者能处理的事项与组织者确认事项也会分开显示。

截图、运行条件和浏览器脚本位于本目录。档案覆盖虚构数据和本地浏览器中的恢复行为；真实模型输入、敏感材料处理、生产并发和公网部署仍需要在授权环境中单独验收。
