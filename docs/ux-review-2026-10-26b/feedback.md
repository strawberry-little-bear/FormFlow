# 验证档案：启动参数与失败状态

这份档案展示首次体验中的恢复路径：自定义端口启动、无效名册路由、无效复核路由，以及提交者与组织者各自的待办。数据为虚构演示数据，模型密钥留空，结果来自本地浏览器。

## 访客可以看到什么

| 场景 | 页面结果 | 下一步 |
| --- | --- | --- |
| 自定义端口 | 启动器检查并使用用户传入的端口，错误提示与实际端口一致 | 修正端口后重新启动 |
| 无效名册路由 | `#/roster/9999` 清除加载占位，说明任务不存在并提供返回工作台入口 | 返回有效任务 |
| 无效复核路由 | `#/review/1/9999` 清除加载占位，只保留主体不存在的错误状态和返回入口 | 选择有效提交者 |
| 提交者进度 | “需要你处理”和“需要组织者确认”分开显示，模型未完成不会伪装成提交者待办 | 处理可操作项或等待组织者 |

## 体验原则

错误状态需要说明发生了什么并给出恢复入口；接口失败后不能继续显示加载占位；责任提示需要让提交者知道哪些事情可以自己完成。以上状态都在页面中保持可见且可恢复。
